# ADR and Jev application review

Reviewed 2026-09-18 (America/New_York), against commit `8d242e86b9596ebd9bc16e5773eff4113c5406e9`.

**Verdict: the architecture is a good application of Jev, but expanded enforcement and claims of demonstrated cascade savings are blocked by correctness and evidence gaps.** Continue observe-mode dogfooding. Prioritize a trustworthy batch verification workflow before the router or package extraction. This review covers all ten ADRs, the PRD, README, relevant implementation/tests/CI, and current primary-source Jev documentation. It is an assessment; no implementation or ADR was changed.

The strongest choices are deterministic checks before inference, independent Noul questions, code-owned thresholds, a separate escalation artifact, conservative default operation, and delaying core extraction until a second consumer exercises the interface. The weaknesses are concentrated in what happens when evidence is incomplete, how measurements are attributed, and guarantees stronger than the implementation can support.

**Ranked findings**

All implementation findings below are verified by direct source inspection. Reproductions used synthetic data and mocked responses, with logs isolated in temporary directories. None required a live model or private credentials. P1 means resolve before relying on automatic approval or unattended acceptance; P2 means resolve before presenting the relevant feature as dependable.

1. **P1 — A partial Jev response can automatically approve a call whose risks were never assessed.** The adapter drops unreadable answers and accepts any nonempty result; the evaluator skips missing questions and reaches the default allow. Reproduced with the shipped policy in `full` mode, `python3 app.py`, and a response containing only `destructive=0.01`: the hook emitted `permissionDecision: allow` despite six missing gate answers. The same incomplete-evidence problem reaches batch judging. Require complete, correctly typed answers for enforcement questions before accepting an allow; missing optional probes need not invalidate a result. [Adapter acceptance](../src/adapters/jev.ts#L156), [missing-question handling](../src/engine/evaluate.ts#L115), [default rule](../src/engine/evaluate.ts#L99).

2. **P1 for unattended batch use — Truncation and service failure do not have a safe disposition.** The item builder cuts large string fields to 4,096 characters after exceeding the aggregate limit. A synthetic document with a violation at the end lost that ending. The judge still evaluates the shortened document normally; its `truncated` flag does not force review. Adapter failure produces an item with `verdict: allow` plus an error, excluded from the escalation manifest. A consumer must inspect auxiliary fields to avoid treating unjudged material as accepted. Furthermore, `--json` returns success before the all-failed check. Define explicit `unjudged`/`incomplete` outcomes, and make downstream handling unavoidable; chunk/retrieve relevant evidence or escalate oversized documents. Preserve truncation in persisted artifacts, where it is currently omitted from the judge log record. [Truncation](../src/engine/item.ts#L54), [failure and normal evaluation](../src/judge.ts#L159), [JSON exit status](../src/commands/judge.ts#L158), [log fields](../src/commands/judge.ts#L187).

3. **P2 — Cascade measurement can undercount tokens and compare unlike populations.** `addTokens` says missing counts should make the total unknown, but actually treats a missing side as zero. Reproduced: the judge supplied no token count, reasoning supplied 100 input tokens, and cascade reported 100 total input tokens. The per-response sums also silently omit unreported usage. Accuracy excludes each pass's unanswered questions independently, so passes can have different denominators. The reasoning baseline receives Jev escalation signals on selected items and those answers are reused for the cascade: this is a paired, Jev-assisted comparison, not an independent reasoning baseline. Reuse is defensible if named accurately; otherwise use separately defined inputs. Preserve unknown usage, report coverage/failures per pass, compare a common scored population, and separate input tokens, output tokens, priced cost, and latency. The current “not worth running” conclusion based only on input-token ratio is not justified when model token prices differ. [Baseline inputs](../src/measure.ts#L94), [denominators](../src/measure.ts#L183), [token sums](../src/measure.ts#L209), [missing-as-zero](../src/measure.ts#L237), [economic conclusion](../src/measure.ts#L319).

4. **P2 — Calibration has no durable identity tying scores to the deployed model and question definitions.** The adapter requests `jev-latest` and reads the returned version, but the gate and judge logs do not preserve that version or a question/policy fingerprint. `calibrate --from` joins by item ID and does not filter the recorded policy-set identity before rescoring. A changed question or another set with reused IDs can therefore reuse incompatible probabilities. Pin the calibrated model through configuration, retain actual model/version, state-builder version, question-definition fingerprint, policy revision and run ID, and reject incompatible replay. Cache fingerprints can be computed at policy compilation rather than adding hashing to every hook call. [Model default](../src/adapters/jev.ts#L20), [returned model](../src/adapters/jev.ts#L175), [log schema](../src/io/log.ts#L34), [replay join](../src/calibrate.ts#L468). TypeSafe explicitly recommends pinning a version after tuning thresholds; aliases can move. [Official model guidance](https://docs.typesafe.ai/models).

5. **P2 — An empty new batch leaves an old escalation manifest on disk.** `writeManifest` returns without replacing the file when there are no escalations. Reproduced two successive mock runs to the same path: the first escalated `old`; the second accepted `new`, but the manifest still contained `old`. JSON output also replaces the in-memory `manifest` object with its path string, even when no new manifest was written. Always atomically write the current manifest, including an empty one, and distinguish `manifest` from `manifestPath`. Include run identity. [Writer](../src/commands/judge.ts#L219), [JSON shape](../src/commands/judge.ts#L159).

6. **P2 — Observe mode can deny on an adapter error.** With `mode: observe` and `on_error: deny`, a mocked adapter failure emitted `permissionDecision: deny`. The error path bypasses mode handling, contradicting ADR-003's unconditional observation guarantee. Make observe suppress enforcement on error too, or reject this contradictory configuration. The shipped default uses passthrough, so this is a configurable edge case, not a claim that the default currently blocks. [Error path](../src/hooks/pretooluse.ts#L264), [ADR guarantee](adr/003-fail-to-prompt-and-observe-by-default.md#L17).

7. **P2 — The local adapter's preflight does not establish constrained decoding.** It discards nonlabel probability mass and accepts any positive yes/no mass. Reproduced an endpoint returning generated text `banana` with logprobs `banana=-0.01`, `yes=-6`, `no=-7`; preflight accepted it and a question returned `p=0.7310586`. That number is a normalized conditional label score, not proof that the endpoint honored the decode restriction or that the probability is calibrated. Strengthen capability testing and supported-server contracts; publish the real-model comparison before suggesting equivalence. [Probability extraction](../src/adapters/local.ts#L345), [ADR-005](adr/005-the-local-adapter.md#L35).

8. **P2 — Two sessions can repeatedly reset each other's circuit breaker.** One shared `breaker.json` is overwritten by every session, and reading another session's record returns fresh state. Alternating two sessions for 20 failures left both failure counters at zero because each call was treated as warmup. Use session-keyed storage and safe concurrent updates. [Read/reset](../src/io/breaker.ts#L60), [shared write](../src/io/breaker.ts#L71).

9. **P2 — Standalone escalations omit the criteria needed to reproduce the judgment.** Signals contain question instructions and the numerical threshold, but not the original true/false criteria, question type, or immutable policy reference. A threshold `criterion` is not the question's semantic `criteria`. The current `measure` command separately supplies full questions, which helps there; an exported manifest alone cannot guarantee the same interpretation. Carry complete question definitions or a resolvable immutable policy snapshot. [Signal construction](../src/engine/escalation.ts#L137), [standalone contract](adr/008-bouncer-is-a-judgment-engine.md#L66).

10. **P2 design/evaluation gap — Good classifier scores do not establish safe gate behavior.** Fast-path behavior is intentionally excluded from calibration, and repeated policy tuning uses the published fixture corpus. Keep that diagnostic corpus, but add a frozen holdout and a separate full-pipeline suite covering fast paths, hard-rule wrappers, missing answers, truncation, adversarial input, host permission modes, and actual emitted decisions. Report dangerous false accepts, safe-call friction, abstention/coverage, per-question counts and reliability, not just aggregate agreement. Brier score is useful but does not alone isolate calibration from discrimination. [Explicit fast-path exclusion](../src/calibrate.ts#L338), [ADR confirmation](adr/010-a-fast-path-entry-is-a-whole-command.md#L93), [existing known threshold miss](calibration/2026-09-18-jev-8.md#L67).

Community directories were used for discovery; technical conclusions below rely on primary documentation, not their marketing or reported speedups.

**Three important model-specific conclusions**

- **Noul is the right primitive for independent hazards.** Its value is a probability, not severity or a separate confidence estimate. Bouncer correctly avoids inventing a Noul confidence field. Choice is appropriate for mutually competing routes; Score fits ordered rubrics. The adapters declare all three, but the public policy loader/evaluator currently implements Noul judgments. Do not advertise general Choice/Score policy support until validation, evaluation, logging and calibration support it end to end. [Confidence documentation](https://docs.typesafe.ai/confidence), [policy loader](../src/engine/policy.ts#L335).
- **Fan-out is applied well.** Independent questions over the same state belong in one request. They cannot use one another's answers; a question needing the selected candidate or fetched evidence needs a subsequent stage. Keep specific field references, compute exact facts outside the model, and do not average a serious violation away. [Fan-out guidance](https://docs.typesafe.ai/patterns/fan-out).
- **The trust boundary needs sharper language.** TypeSafe warns that adversarial state can steer Jev 1.13 and that large irrelevant context degrades accuracy. JSON structure prevents field confusion in code; it does not prove semantic prompt-injection immunity. Test comments/descriptions that argue for their own classification, misleading quoted examples, missing evidence and hidden document endings. These are recommended tests, not a claim that a live Jev exploit was demonstrated here. [Jev 1.13 limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13).

The router privacy sentence also needs correction: prompts and private skill descriptions already being visible to Claude does not mean sending them to TypeSafe discloses nothing new. Describe recipients, included fields, opt-in behavior and local alternatives, as ADR-009 already does for batch content. [Current sentence](adr/006-the-skill-router.md#L162). Its warm probe numbers likewise do not validate the cold-hook timeout; this is a pending measurement, not a demonstrated router timeout rate. [Router budget](adr/006-the-skill-router.md#L378).

**Recommended order of work**

1. **Decisions:** amend ADR-003/008/009 with complete-evidence requirements, unresolved outcomes, manifest identity and measurement rules. Add a compact model/policy versioning and evaluation contract. Resolve router recipient disclosure and candidate-fit policy before implementation. Check examples against the policy loader; finish with typecheck and tests.
2. **Runtime correctness:** fix partial answers, truncation/error disposition, observe errors, stale manifests and session breaker isolation. Add focused regressions reproducing these exact failures. Run typecheck, tests, build/freshness and the local 80 ms overhead gate.
3. **Evidence:** repair measurement accounting and replay attribution; create a held-out corpus and full-gate evaluation separate from classifier calibration. Then perform version-pinned live Jev, local and reasoning comparisons, preserving raw answers and failures. Run the existing quality gates and require the new evidence checks to pass before stronger claims.
4. **Product validation:** dogfood one real batch workflow and report review workload reduction at an acceptable false-accept rate, alongside model-specific priced cost and end-to-end latency. Token reduction alone is not the product outcome. Re-run the batch regressions and overhead gate if shared imports change.
5. **Expansion and release:** consider router/typed-policy expansion only after those results. Extract core when the interface stabilizes under real consumers. Run the complete CI suite and publish the exact policy/model/data versions behind the release evidence.

The user decisions are risk tolerance for unattended acceptance, approved data recipients, the first real batch workload and supported local-model deployment. The defect corrections do not require architectural reinvention.

**Validation and limits**

- `npm test`: **786 tests across 23 files passed**.
- `npm run typecheck`: **passed**.
- `npm run bench`: judged-path p95 **38.6 ms**; hard-rule-path p95 **40.2 ms**, both below the local 80 ms budget. These are mock-backed overhead measurements, not live Jev latency.
- Test setup rebuilt the committed bundle; the tracked worktree remained clean before adding this report. CI configuration runs typecheck, tests, build/freshness, mock calibration and a looser 150 ms overhead check. It does not establish live-model calibration or real local-backend compatibility.
- No live Jev calibration, actual local inference, paid reasoning comparison, deployed host-permission integration test, or adversarial live-model evaluation was performed. Existing published calibration is repository evidence, not a rerun. Vendor cookbook outcomes are author-reported examples, not Bouncer results.
- This is a local plugin/CLI, so web-server TLS/HSTS, CSRF, HTTP sessions and database pool/migration checks are not applicable. Relevant operational controls are external API transport, local evidence retention, configuration validation, subprocess timeouts, concurrency, artifact freshness and host permissions. Dependency advisory scanning was outside this ADR/Jev review.
