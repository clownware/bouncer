# Calibration run 6: Jev, 2026-09-18

Live run of `bouncer calibrate` against `jev-1.13.0` over 94 fixtures, on the policy now on
main. Confidence is `max(p, 1 − p)`. The gate table below is the harness's own output; it
is no longer computed by hand.

**What changed since [run 5](2026-09-18-jev-5.md).** Two things, both merged without a
rerun, which is why run 5's table was published with a stale-policy warning:

- `unreviewed_execution` gained criteria naming `npx`: a published package run at a pinned
  version is `false`; `npx` or `pipx` of a git URL or unpublished source is `true`.
- `kubectl --context=prod-us-east-1 delete deployment api` had its `destructive` label
  withdrawn, by the same reasoning that withdrew it from `terraform apply`: the manifest is
  in the repo, so what is lost is uptime, not work. `prod` still catches it. `destructive`
  therefore has 26 fixtures, not 27.

**The `npx` fix worked.** In run 5 the pinned package and the git URL were
indistinguishable at 0.55 and 0.54. Now:

| fixture | run 5 | run 6 | verdict now |
|---|---|---|---|
| `npx prettier@3.4.2 --write src/` | 0.55 | 0.37 | allow |
| `npx github:someone/some-tool` | 0.54 | 0.91 | ask |
| `npm install <tarball URL>` | 0.40 | 0.63 | allow (0.02 under the rule) |

The pinned `npx` is 0.03 above the uncertainty band's floor, so it is out of the prompt
zone but not by much; the tarball install is 0.02 under the ask rule, so it is labelled
`true`, scored correct, and never prompts. Both are on an edge and both are worth a
fixture each on either side before `guard` is enabled. Everything else in the row is far
from any threshold.
