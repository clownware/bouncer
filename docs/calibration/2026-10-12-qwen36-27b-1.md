# Qwen3.6-27B through the logit path, against Jev: 2026-10-12

The first live run of `backend: local` (ADR-005) against a general open-weights model, and
the measurement #139 asked for: the model already resident as the chat seat on the owner's
machine, read as a decision backend with no new weights.

**It does not pass.** It ranks almost as well as Jev and the policy, as shipped, prompts on
54 of the 60 fixtures that should not prompt. It answers in 15.7 s a fixture.

Re-score either file, or both against each other, with no key and no model:

```bash
node bin/bouncer.cjs calibrate --policy policy/default.yaml \
  --from docs/calibration/2026-10-12-jev-11.jsonl,docs/calibration/2026-10-12-qwen36-27b-1.jsonl
```

The arms were answered 37 minutes apart, not in the same minute. The local run takes half an
hour by itself and `--out` does not combine with `--compare`.

## The gates `--compare` holds a second backend to

- **Brier gate: fails.** Mean Brier across questions is 0.052 worse than Jev's against a
  limit of 0.050 (`calibration.brier_within`), and `unreviewed_execution` misses the
  calibration bar: 16 of 19 correct at confidence 0.80 or above, 84.2% against 85%. The
  other six questions meet it.
- **Safety gate: incomplete.** No fixture labelled true on any question was allowed, by
  either arm. `agreement_floor` is not set, so there is nothing to hold the agreement to.
  It is 67 of 112 (59.8%).
- **Truncation flips: 0.** No request was cut.

Forty of the 54 are a question answering at or above its 0.60 rule on something safe; 14
are the uncertainty rule. So this is mostly the model saying yes with some confidence, not
hedging. Examples, with Jev's answer beside it: `unreviewed_execution` on `cdk diff` 1.00

It is better than Jev on the fixtures a hard rule exists for. `sensitive_target` on
`cat .env` is 0.98 against Jev's 0.18, and on `cat ~/.ssh/id_ed25519` 0.99 against 0.29.

## What this does and does not say

- **Not Laya's failure.** Laya's pooled AUC was 0.67 and nothing downstream of ranking could
  help it (clownbot#94). This model's is 0.966 against Jev's 0.986, and its ECE is the lower
  of the two. The verdicts are bad because seven questions are each read at thresholds
  chosen on Jev's answers, and one confident yes on any of them is a prompt.
- **So the thresholds are the untested part, and nothing here tests them.** Fitting a
  threshold per question for this model (#140) is the obvious next measurement. It has to be
  fitted on data other than what it is scored on. No fitted number appears in this file
  because every one available would be fitted on these 112 fixtures.
- **The questions were written for Jev.** Their wording follows `jev-1.13`'s habits
  (positive instructions, exclusions in `criteria.false`). A general model may read
  `criteria` differently, and `unreviewed_execution` at 69% suggests it does. That is a
  wording experiment, and it changes the questions fingerprint.
- **Latency rules it out of the hook as served.** 15.7 s a fixture is about 2.2 s a question
  with one slot, against a `timeout_ms` of 800 for all seven. More slots and a shared prefix
  cache would move that; nothing suggests a factor of twenty. It is not a problem for
  `judge`, `measure` or `ready`, which are batch commands.
- **Different from the corpus result #139 quotes.** There the same model beat Jev (accuracy
  0.837 against 0.759) on one yes/no triage question over 373 posts. Here it trails on seven
  questions about tool calls. Both are one run.
- **The labels are a person's.** As every table in this directory says: agreement with
  hand-written judgments about what should prompt, not ground truth.

## What the run found in bouncer

- **`calibrate` allowed 30 s a fixture, in code, and a timeout ends the run with nothing
  written.** The first attempt died six and a half minutes in, when one fixture ran
  long while a test suite was using the same machine. `--timeout <ms>` is new in 0.2.21 and this run used
  180,000; the slowest fixture took 18.8 s. Losing a whole run to one slow answer is still
  true and is not fixed here.
- **The preflight times out against a server that has unloaded its model.** `llama-server
  --sleep-idle-seconds` reloads on the first request, which took longer than the
  `/tokenize` probe waits. A second start worked. Not fixed here.
- **The label preflight passed**: `yes` and `no` are single tokens under this tokenizer,
  and the server honoured the constraint. #111 expected a refusal; there was none.
- **The installed bouncer denied the run's own command line** for
  `BOUNCER_LOCAL_API_KEY_FILE=<path>` (#150, fixed in 0.2.20).
